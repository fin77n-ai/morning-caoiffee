# 月度专题运行说明

## 这版做什么

- 原每日 Telegram 简报改为手动触发；邮件仍保留原有手动流程。
- 新工作流每周一北京时间 07:00 推送一篇专题导读，正文和四篇目录都在 `docs/topics/`。
- 首期四篇采用可审阅的编辑稿，不调用模型生成正文；不依赖当天抓取结果，也不消耗 DeepSeek 配额。
- `config/monthly-topics.json` 保存主题、开放月份、篇目、导读和问题。`data/topic-deliveries.json` 保存已推送记录。
- 每个自然周最多推一篇，重复手动触发不会补发。漏跑后从下一篇继续，不一口气补推；跨月先推完旧专题。
- 四篇都推完且没有已开放的新专题时保持安静。不会自动猜下个月主题。
- 全部正文随代码发布即可阅读。发送记录不代表阅读记录；这版不提供自动“读到哪里”或重大新闻提醒。

## 预览与启用

```sh
npm ci
npm run topic:preview
npm test
```

预览只显示下次导读，不发送、不写入记录，也不需要凭据。合并到默认分支 `main` 后周计划才生效。已有 `TELEGRAM_BOT_TOKEN` 和 `TELEGRAM_CHAT_ID` 可以复用；无需增加密钥。`npm run topic:send` 和工作流手动触发都会真实发送。

首期从 2026 年 10 月开放。由于启动在月中，剩余篇目可能延续到下月；月份是专题归属与最早开放月份，不是阅读期限。GitHub 定时任务可能延迟，07:00 是计划时间。

## 添加下一期

1. 在 `docs/topics/<新专题 ID>/` 编写四篇 Markdown 正文和 `README.md` 目录。
2. 在配置的 `topics` 数组增加一个独立 ID、月份和四篇的文件名、导读、阅读问题。
3. 在 `docs/topics/README.md` 加入新专题链接。逐条核对参考资料、目录和前后篇链接。
4. 本地预览、运行检查，再发布。配置支持未来月份，尚未开放的专题不会提前推送。

新资讯可经过编辑后作为相关章节的补充案例，注明日期和出处；第一版没有自动抓取、筛选和插入专题案例。

## 失败与恢复

读取到损坏的推送账本会停止，避免重新从第一篇开始。Telegram 请求失败时不记为已发送。

Telegram 发送与 GitHub 提交不是一个事务。消息已送达但记账或推送 GitHub 失败，重试可能重复发送；请求超时也可能发生“已送达但未收到响应”。先检查 Telegram，再检查失败运行的 `topic-delivery-history` artifact 与仓库账本，恢复已发送的篇目记录后再重跑。不要只重跑发送步骤。上传 artifact 也失败时，可按账本现有格式手工补齐 `topicId`、`chapterId`、上海本地 `day` 和该周周一 `week`。

自动工作流用 concurrency 串行运行；它无法约束其他电脑直接运行发送命令。GitHub Actions 必须允许仓库内容写入，否则通知后的账本推送会失败。
